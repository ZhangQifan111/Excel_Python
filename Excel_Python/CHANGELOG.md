## [2.8.2] - 2026-03-30

### 🐛 Bug修复

#### 修复故障码被意外清空的问题
- **问题描述**：运行故障分析时，`_analyze_fault_data` 方法重复调用加载函数，导致已加载的故障码被清空
- **根本原因**：
  1. 模块初始化时已正确加载点表格式（629个故障码）
  2. `_analyze_fault_data` 再次调用 `load_fault_codes_from_point_table()`
  3. 由于"首次定义优先"，函数返回 `False`
  4. 条件判断触发 `load_fault_codes_from_excel()`
  5. `load_fault_codes_from_excel()` 执行 `MAIN_FAULT_CODES.clear()` 清空了所有数据！
  
- **修复方案**：
  1. `_analyze_fault_data` 不再重复调用加载函数
  2. 只在 `total_bits == 0` 时才尝试加载
  3. 避免清空已加载的故障码定义

#### 修复流程对比
```
修复前:
1. 模块初始化: 加载 629 个故障码 ✅
2. _analyze_fault_data: 再次调用加载函数
3. 返回 False（数据已存在）
4. 触发 load_fault_codes_from_excel()
5. MAIN_FAULT_CODES.clear() 清空数据 ❌
6. 20663 bit0 解析失败 ❌

修复后:
1. 模块初始化: 加载 629 个故障码 ✅
2. _analyze_fault_data: 检查 total_bits = 629
3. total_bits > 0，跳过加载
4. 20663 bit0 解析成功 ✅
```

## [2.8.1] - 2026-03-30

### 🐛 Bug修复

#### 修复故障码解析问题
- **问题描述**：20663寄存器bit0（逆变软件过流）无法正确解析
- **根本原因**：
  1. `load_fault_codes_from_point_table()` 函数未正确解析"平台逆变器错误代码对照表.xlsx"的点表格式
  2. 加载优先级错误，导致部分故障码定义被覆盖

#### 修复内容
1. **修正点表格式解析**：
   - 正确识别标题行（包含"寄存器偏移量"的行）
   - 使用正确的列索引（列1=偏移量，列7=故障ID，列9=中文名称）
   - 跳过标题行，从数据行开始解析

2. **调整加载优先级**：
   - 优先加载"平台逆变器错误代码对照表.xlsx"（点表格式），因为它包含完整的bit定义
   - 其次加载"户储光伏平台产品客户故障码.xlsx"（故障码定义表格式）

3. **首次定义优先**：
   - 对于同一寄存器的同一bit位，保留首次遇到的定义，不覆盖
   - 解决了多产品型号使用同一寄存器地址的问题

#### 验证结果
```
20663 bit0: 逆变软件过流 ✅
20663 bit1: R相逆变硬件过流 ✅
...
加载故障码数量: 629个（43个寄存器）
```

## [2.7.1] - 2026-03-30

### 🐛 Bug修复

#### 故障码解析修复
- **修复多行映射格式解析**：Excel中的映射关系采用多行格式（如 `20650：\nbit5...\nbit6...`），原正则表达式只能匹配第一行
- **修复bit位缺失问题**：修复了 bit6、bit7 等后续bit位无法解析的问题
- **故障码定义数量**：从60个增加到167个

#### 解析逻辑优化
- 改用两阶段解析：先定位寄存器位置，再提取该范围内的所有bit
- 支持多种映射格式：`bit5（描述）= 1`、`bit5 = 1`、`bit5`

### 📝 技术细节

- 问题原因：原正则 `(\d+)\s*[：:]\s*bit(\d+)` 只能匹配 `20650:bit5` 格式
- 解决方案：先匹配 `20650：` 定位寄存器，再从后续文本提取所有 `bitN`

- **整体一致性检查**：所有选择的列必须同时增加、同时减少或同时不变
